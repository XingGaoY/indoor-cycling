## 项目定位与目标

本项目用于持续开发、部署和维护个人室内骑行与有氧交叉训练系统。产品服务于长期有氧训练、跑步交叉训练和训练数据积累；目标是在需要时通过家庭骑行设备替代或补充户外运动。强调可靠、安全、可测试、可迁移和数据自主权，而非依赖商业训练平台。

最终使用体验应为：家庭主机连接并管理训练设备，使用者通过手机操作训练并查看实时状态，训练结束后保留完整可靠的记录，并尽可能通过正式、可持续的方式与已有训练生态同步。

## 开发与协作模式

- GitHub 仓库 XingGaoY/indoor-cycling 是代码、文档、测试和决策记录的唯一权威来源。开展工作前先查看仓库当前状态，勿依赖对话中的过时方案。
- 以小步、可验证、可回滚的增量迭代为主。优先使用分支和 Pull Request，测试通过并审查后合并到稳定分支。
- 每次改动说明目标、改动、测试结果、风险和未验证事项。涉及用法、接口、配置或部署变化时，同步更新 README 与 doc/ 中的对应编号文档。
- 避免无关的大规模重构和重复建设；保持模块化、可维护、易于其他机器和开发者接手。
- 明确区分已实现、已自动测试、已实机验证和仍属计划的功能。不得把模拟结果表述为真实设备实测。
- 硬件相关改动以安全优先，必须有明确控制边界、错误处理和可退出路径。

## 部署与数据原则

- 目标部署形态是家庭 macOS / Mac mini 常驻主机承担设备连接、训练执行与数据保存，手机 Web/PWA 负责交互；浏览器不应成为设备控制的唯一状态来源。
- 项目应支持在新机器上从 GitHub 独立部署、在其他开发环境继续开发，并具备清晰的配置、升级、故障诊断及回滚说明。
- 本地数据优先，尽量使用开放标准，避免不必要的商业平台和私有云依赖；外部同步需区分正式支持、已验证的能力与实验方案。
- 训练控制、数据和账号凭证均应采取保守的安全默认值；不公开暴露未经加固的控制服务，不将私人训练记录或密钥提交到代码仓库。
