# 10 · 可视化课程编辑器：时间轴、功率／心率区间与预设

> 状态：v0.1 第一版实现与后续设计约束（2026-10-12）。本文件是 **技术/产品设计**，不属于长期 ChatGPT Project instruction。已实现功能以 [07](07-status-and-acceptance.md) 与实测为准。

## 1. 用户目标与最小可用交互

室内骑行的课程应像绘制一条强度曲线一样直观，而不是逐页填写繁琐表单。

- **横轴：有效训练时间。** 区块横向宽度严格等于阶段时长乘以统一缩放比例（默认 24 px/min），不会为了让短块可点击而强加最小宽度。起点和首个刻度都为 **0:00**；按课程总时长显示 5/10/15 分钟固定刻度，且提供放大/缩小、横向滚动。拉右侧把手以 30 秒为步长调整时长。
- **纵轴：训练区间 Z1–Z6。** 可以在**功率**／**心率**两个视图间切换，二者始终指向同一份课程和同一条时间轴，而不是创建两套独立课程。
- 从时间轴左侧的**形状工具栏**选择恒定矩形、递增梯形、递减梯形或间歇组。点击工具追加在末尾，或拖入时间轴并按放下位置插入。添加后选中块，再设置目标 Z 区间。移动设备上允许通过下方的编辑区精确调整数值，不能强迫只使用拖动操作。
- **块内**以阶段名称及其**自身时长**为主；**块上方**按当前功率/心率视图显示目标，例如 Z2 或已校准后的 W/bpm，仅显示当前视图，不叠放双指标。点选区块后下方显示名称、用途、时间、功率配置与心率目标；上下拖动改变当前目标区间，右侧把手调整时长。小于展示宽度的标签可以省略，由下方精确编辑显示完整值，不允许为放标签而歪曲时间轴。精确调整、复制、删除、顺序交换可通过辅助按钮完成。
- 同一行课程的恒定目标显示为平顶区块，线性功率变化为斜坡。间歇组**默认折叠为一个带微型工作/恢复预览的组合块**，组合块显示重复次数及**整体时长**；点击后展开全部轮次，展开后的每一子块仍遵循严格时间比例。对子阶段的编辑会影响全部重复轮次。
- 课程编辑保存后留在 SQLite；**选中计划不是训练执行**，现有主页仍是自由模拟训练，不进行 FTMS 写入。

## 2. 区间基准和显示规则

功率基准建议使用个人 **FTP** 而不是单次冲刺最大功率；心率第一版使用个人 **最大心率**。基准值默认为 null，**绝不预填未经测量的 FTP 或 HRmax**；用户可以在编辑页设置或清空基准，保存到本地 `workout_settings.zone_settings`。

功率分区（占 FTP 百分比；Z6 无上界，数值为常见六区近似，需要个性化校准）：

| 功率区 | FTP 比例 | 用途 |
| --- | --- | --- |
| Z1 | 0–55% | 恢复 |
| Z2 | 55–75% | 耐力 |
| Z3 | 75–90% | 节奏 |
| Z4 | 90–105% | 阈值 |
| Z5 | 105–120% | VO₂ |
| Z6 | >120% | 无氧（不应当当成无限可执行功率） |

心率分区第一版是基于 HRmax 的**可配置演示分区**；不同运动之间不能机械套用，也不代表高驰自己的分区标准：

| 心率区 | HRmax 比例 |
| --- | --- |
| Z1 | 50–60% |
| Z2 | 60–70% |
| Z3 | 70–80% |
| Z4 | 80–90% |
| Z5 | 90–95% |
| Z6 | 95–100% |

实际用户训练中心率下限或上限可与主功率目标不一致。现阶段 `hr_zones` 仅表示计划注释/未来提醒目标，**既没有实时自动校正，也没有启用闭环 ERG**。以后可以加入 LTHR 方案与个性化区间，但必须带版本化区间定义，不能默默改变既有历史课程的含义。

当 FTP 或 HRmax 尚未设置时，纵轴依然显示 Z1–Z6；不显示捏造的 W/bpm。设置后在轴标签展示相应参考范围。由于心率的生理延迟，心率页面应该表达允许区间，而不是假设与功率目标逐秒重合。

**计划功率不等于硬件功率安全上限。** 编辑器允许 40–500 W 的传统绝对值阶段，FTP 区间的 Z6 无上界；任何真实 ERG 控制以后都必须另按骑行台能力、启动前校准和安全策略二次限制。当前训练 API 模拟功率上限仍为 150 W。

## 3. 数据模型与旧数据兼容

继续沿用 `workout_plans` 表中的 JSON 文档。只有阶段级别新增可选字段：

- `power_zones: {"from": 1..6, "to": 1..6}`：有该字段时按 FTP **相对功率目标**解释，不需要也不得自动填入编造的绝对瓦数。恒定 `kind=constant` 必须 `from=to`；线性 `kind=ramp` 可从任一区间变化到另一区间。
- 旧版本没有 `power_zones` 的阶段继续使用 `watts` 或 `start_watts/end_watts`（40–500 W 整数），可以在编辑器切换成区间模式。**旧课程无需强制迁移或删除。**
- `hr_zones: {"from": 1..6, "to": 1..6}`：可选心率提醒/目标区间，必须 from ≤ to；没有该字段即没有心率约束。
- 间歇组仍为 `kind=repeat` + `repeat_count` + `steps`；当前仅支持一层循环、子阶段不可再嵌套间歇组。
- 阶段时间整数秒，10–7200；间歇次数 1–30；课程总时间不超过六小时；最多 30 个顶层块，间歇内 2–10 个子块。

例子：

~~~json
{
  "name": "我的 Z2",
  "note": "按 FTP Z2 规划；未设置 FTP 不可用于真实 ERG",
  "stages": [
    {
      "kind": "constant",
      "name": "耐力段",
      "purpose": "main",
      "duration_s": 1800,
      "power_zones": {"from": 2, "to": 2},
      "hr_zones": {"from": 2, "to": 3}
    }
  ]
}
~~~

这份 JSON 只描述**计划**。未来在开始训练时要保存不可变快照：使用当次区间定义/FTP/HRmax + 每个阶段的确定目标，并明确记录有无真实硬件能力校验。本 PR 尚未实现执行器或训练快照。

## 4. 预设课程（模板，不是处方）

在 `/plans` 的“预设课程”区域提供四个**内置只读模板**。单击“复制到我的课程”才创建用户可编辑副本；不在每次启动时自动添加到个人库，也不会覆盖已有课程。重新部署后从源码仍能看到模板；用户自己的计划只在 SQLite 保存和备份。

| 名称 | 阶段 | 总时长 | 适用目的 |
| --- | --- | --- | --- |
| 轻松恢复 · 30 分钟 | Z1 5′ / Z1 20′ / Z1 5′ | 30′ | 力量训练后轻活动，按体感调整 |
| Z2 有氧 · 45 分钟 | Z1 8′ / Z2 32′ / Z1 5′ | 45′ | 污染天气的低冲击有氧补充 |
| 节奏训练 · 40 分钟 | Z1 10′ / Z2 5′ / Z3 15′ / Z2 5′ / Z1 5′ | 40′ | 有骑行适应之后的节奏训练 |
| 阈值间歇 · 43 分钟 | Z1 10′ / 4×(Z4 4′ + Z1 2′) / Z1 9′ | 43′ | 结构化课程编辑演示，非新手强度推荐 |

表格中的心率区间只是粗略提示，不是为了追到区间而不断调整 ERG：心率反应滞后且与跑步不完全等价。没有 FTP/HRmax 校准前，预设课程**不能直接换算为安全的设备功率指令**。

## 5. 后端 API

与已存在的 `/api/plans` CRUD 共用 `X-Cycling-Token`：

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| GET | /api/plans/presets | 返回模板 ID、名称、说明、时长和展开阶段数 |
| POST | /api/plans/presets/{slug}/copy | 将预设复制为普通用户课程 |
| GET | /api/plans/zones | 查询功率/心率分区与当前个人基准 |
| PUT | /api/plans/zones | 更新 `{"ftp_w":null/int,"hr_max_bpm":null/int}` |

只允许合法参数；FTP 必须是 60–500 整数或 null，HRmax 必须是 100–230 整数或 null；每个区间 1..6。重复模板复制会生成不同 ID，这是用户主动创建副本的语义，不自动去重。现有 plan CRUD 与选择 API 不改变执行语义。

## 6. 交互及异常行为

- 在没有保存内容时关闭编辑器会丢弃本次改动；本版提供明确的保存和取消。下一步可添加脏状态离开确认、撤销/重做与更精细的滑动体验。
- 左侧形状工具栏：恒定矩形、递增梯形、递减梯形、间歇组。点击追加；按住拖入时间轴在落点附近插入。工具不再按 Z1–Z6 分类；强度在选中阶段后编辑。
- 上下拖动区块改变所选视图区间，恒定块只设一个 Z；斜坡两端按相同偏移移动并裁剪到 Z1–Z6。左/右端点及功率绝对值的精确设置留在下方编辑器。**不将水平拖动整块解释为修改时长**；调整时长仅使用右侧把手或精确编辑。
- 右侧把手调整阶段持续时间（30 秒步进）；缩放默认 24 px/min，支持 12–72 px/min，可横向滚动。间歇默认折叠，点击展开；展开的每轮复用组内源数据，不允许某轮悄悄偏离其他轮。
- 一旦心率目标丢失或传感器超时，未来执行时必须显示过期/未知，不能用虚构的实时心率代替。
- 加载、保存和网络错误要给用户明确提示；未经正式 HTTPS/认证加固，页面只在主机本地或受保护隧道中运行。
- 不对真实运动设备产生任何蓝牙写入；只有用户显式开始未来的已验证训练执行器，才可以尝试控制设备。

## 7. 下一个工程阶段

1. **真实手机手势验证**：在 Safari 中检查形状工具拖放、组合展开、窄块选中与缩放滚动；目前自动测试不能替代此验收。
2. **训练执行内核**：课程快照 + 区间基准快照、有效训练时间、单层间歇展开、跳过、暂停、阶段偏移与重启中断。
3. **训练页关联**：选中课程后显示目标曲线、当前阶段、下一阶段与剩余时间；未实现真实 ERG 时全部保持明确模拟标签。
4. **手机交互优化**：在 Mac mini 和真实手机 Safari 上验证触屏拖动、滚动、键盘/辅助操作；添加撤销/重做、拖动排序、复杂间歇可视展开。
5. **真实硬件验证**：严格独立于本视觉编辑器，先 FTMS 能力探测与无控制权写入的安全诊断。
6. **FIT 导出**可以在数据模型稳定后实现；COROS 自动上传暂缓，不能阻塞编辑与训练。
